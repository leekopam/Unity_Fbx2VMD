# 2026-09-30 Magica Cloth 2 물리 작업 — 전용 워크트리 이관 및 마무리 계획서

## 배경 (검증된 사실)

- 본 워크트리(`Unity_Fbx2VMD`)의 미커밋 물리 작업물이 외부 정리로 삭제됨.
  최신본은 `-lowerbody` 워크트리(`agent/lowerbody-physics`)에 존재.
- `-lowerbody`는 **하체 보정 작업선 소유**(UnityLockfile 존재 = 에디터 점유 중).
  거기서 직접 작업하면 역오염 → **전용 워크트리 신설**이 정답.
- `-lowerbody`의 dirty 상태엔 두 작업선 변경이 혼재 → 파일별 선별 이관 필수.
- `*.fbx`/`*.fbx.meta`는 gitignore(커밋 57377c94) → 신규 워크트리엔 모델 없음.
  본 워크트리의 `isReadable:1` 미쿠 메타도 로컬 전용.
- Library는 워크트리 간 공유 불가(junction 불안정 보고) → 첫 임포트 비용 수용,
  장기적으로 Unity Accelerator 도입 검토.
- NRE 유력 원인: `EditorSettings.m_EnterPlayModeOptions:3`(도메인/씬 리로드 비활성)
  + MC2 `managers`가 `SubsystemRegistration`에서만 생성되는 초기화 순서 엣지.
- 시작 스파이크(3.9s, 1회성): 셰이더 컴파일/Mono JIT/MC2 init 중 어디인지 미분해.
  완화 수단: `ShaderVariantCollection.WarmUp`(DX11 유효), 로딩 단계 이관.

## 환경 규칙 (이 계획 전 구간에 적용)

1. 작업 단위 = worktree + 전용 브랜치. 다른 워크트리 경로를 대상으로 하는
   `git clean`/`reset --hard`/`checkout .` 금지 (자기 워크트리 내부도 `-n` 드라이런 선행).
2. Unity 에디터 = 프로젝트 경로당 1개. 물리 검증은 전용 워크트리의 에디터에서만.
3. 의미 단위마다 WIP 커밋 — 미추적 상태로 두지 않는다(유실 보호의 유일한 수단).
4. 다른 작업선의 파일(진단도구, 하체 보정, VMD 프로브, Profiling 계열)은
   이관·수정 대상에서 제외.
