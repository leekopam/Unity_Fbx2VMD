# 캐릭터 물리(머리카락/옷/장식) 적용 작업계획서

날짜: 2026-09-29
상태: 계획 수립 완료, 구현 미착수
근거 자료: MagicaCloth2 물리 적용 조사 (이전 세션 연구 결과)

---

## 1. User Goal

캐릭터 모델의 머리카락·옷·장식물에 물리를 적용한다.

- 머리카락이 신체/옷을 관통하지 않아야 한다
- 머리카락이 아무리 길어도 손·발에 꼬이거나 걸리지 않아야 한다
- 어떤 캐릭터 모델이든 동일 파이프라인으로 적용 가능해야 한다

## 2. Problem Statement

모델 포맷(MMD/VRM/FBX)마다 머리카락 본 구조와 명명이 다르고, 물리 콜라이더는 수작업 배치가 기본이라 모델마다 반복 작업이 필요하다. 관통·꼬임은 단일 파라미터로 해결되지 않고 콜라이더 배치, 백스톱, 관성, 충돌모드의 조합 문제다. 수동 세팅 방식으로는 "어떤 모델이든" 요구를 충족할 수 없으므로, Humanoid 본 기반 자동화 + 부위별 전략 + 검증 파이프라인이 필요하다.

## 3. Project Context Used

- MagicaCloth2 **v2.18.1** 설치됨 (`Assets/_Project/Plugins/MagicaCloth2`)
  - 시메트리 `AutomaticHumanBody` 사용 가능 (v2.15+)
  - Surface/Collider Penetration 제약은 **MC2에 없음** (MC1 기능) — 콜라이더+백스톱+Edge+애니메이션포즈 조합으로 대응
- UniVRM v0.130.1, MMD4Mecanim, YYB Hatsune Miku 모델 존재
- Humanoid 본 매핑 인프라 존재 (`EditorHumanoid*` 계열)
- 프로젝트에 물리 관련 코드 없음 (신규 구현)
- 캡처/테스트 인프라 존재 (`TestResults-*.xml`, `Screenshots/` 등 QA 파이프라인)
- MMD4Mecanim은 PMX 물리를 Bullet으로 베이크 — MC2 적용 시 이중 물리 주의

## 4. In Scope

1. **콜라이더 자동 생성기** (Humanoid 전제)
   - 머리 구, 목 캡슐, 가슴 캡슐, 허리 큰 구(뚜껑 역할), 어깨~위팔 캡슐, 아래팔 캡슐, 손 구, 허벅지 캡슐
   - 한쪽만 만들고 `AutomaticHumanBody` 시메트리로 반대쪽 자동화
   - 콜라이더 크기는 본 길이·위치 기반 자동 산출 + 보정 계수
2. **머리카락 본 자동 감지**
   - `HumanBodyBones.Head` 자식 중 Animator 미할당 본 체인 스캔 (공통 fallback)
   - 본명 패턴: 영어(hair/tail/braid/pony/side/back/front) + 일본어 MMD(髪/前髪/後髪/横髪/ツインテール/アホ毛) + L/R 구분
   - VRM 경로: VRMSpringBone 메타데이터가 있으면 체인 정보로 활용
   - 감지 실패 시 수동 루트 본 지정 진입점 제공
3. **부위별 BoneCloth 자동 생성**
   - 앞머리/옆머리/뒷머리/꼬리류 분리 생성, 캐릭터 루트(Animator) 직하 배치, 의미있는 명명
   - 부위별 프리셋 자동 적용 (FrontHair/LongHair/PonyHair/Tail)
   - 앞머리 백스톱 자동 설정 (Normal Alignment → 머리 중심 Transform)
4. **부위별 ColliderList 자동 매핑**
   - 앞머리: 머리+목+어깨 | 뒷머리: 상반신+팔 전체+손 | 스커트류: 하반신+허리
   - 32개 제한 내에서 관련 콜라이더만 선별
5. **관통/꼬임 억제 파라미터 템플릿**
   - Inertia(World/Local Speed Limit 0.3~1.0, 회전 ~100), Teleport(Keep/0.03/45), Friction 낮춤, Radius 넉넉히
6. **검증 파이프라인**
   - 검증 애니메이션(회전/댄스/손 휘두르기) 재생 + 관통 샘플링/스크린샷
   - Cloth Monitor 기즈모 활용 가이드

## 5. Out of Scope

- MeshCloth 자동 버텍스 페인트 (수동 조정 영역 — 1차는 BoneCloth 계열만)
- 셀프 콜리전/상호 충돌 (실험적·고부하, 별도 단계)
- PhysBone→MC2 완전 변환기 (Inside Bounds 등 대응 불가 기능 있음)
- WebGL/VisionOS 지원 (MC2 미지원)
- MMD4Mecanim Bullet 물리 교체/제거 — 병존 가능 여부만 확인
- VRChat/멀티플레이 연동

## 6. Required Resources

- MagicaCloth2 v2.18.1 (설치됨), 런타임 구축 API (`SerializeData`, `BuildAndRun()`)
- Humanoid Avatar가 설정된 테스트 모델: YYB Miku(MMD, 일본어 본명) + VRM 모델 + 일반 FBX 각 1개
- 검증용 애니메이션 클립 (기존 VMD/FBX 재생 인프라 활용)
- 참조 도구 소스: MagicaClothColliderBuilder(GitHub), zenn SAColliderConverter2 스크립트

## 7. Assumptions

- 테스트 대상 모델은 Humanoid Avatar로 설정 가능 (Generic 전용 MMD 모델이면 수동 콜라이더 경로로 fallback)
- 머리카락 본이 모델에 존재 (본 없는 메시 머리는 MeshCloth 영역 — 이번 범위 밖)
- 에디터 Unity 버전과 MC2 2.18.1 호환 상태
- 캐릭터 등장 후 수 프레임의 런타임 구축 지연 허용 (필요 시 Pre-build 검토)

## 8. Risks

| 리스크 | 완화 |
|---|---|
| Humanoid 미설정 모델 → 자동화 전제 깨짐 | Generic 시 수동/본명 스캔 경로 명시, 자동감지 실패를 오류 아닌 경고로 처리 |
| MMD 일본어 본명 패턴 불완전 | 패턴 목록 + 미감지 시 수동 지정 UI 진입점 |
| 콜라이더 자동 크기 부정확 (자동생성은 작게 나오는 경향) | 생성 후 씬 뷰 확인 워크플로 + 보정 계수 노출 |
| 32개 콜라이더 제한 초과 | 부위별 ColliderList 선별 설계로 내포 |
| 팔 빠른 동작 시 찰나 관통 | 파티클 Radius↑, Edge 모드, Distance Stiffness 끝쪽 강화 (디버깅 사다리 문서화됨) |
| 런타임 구축 지연으로 등장 직후 물리 미적용 | 수 프레임 허용 or Pre-build 옵션 |
| 셀프콜리전 없이 머리끼리 얽힘 | 요구사항 미포함(신체/손발만). 기대치 조정 필요 시 명시 |

## 9. Worker Task Brief

구현 파일 위치: `Assets/_Project/Scripts/Physics/` (신규 폴더) 또는 기존 스크립트 구조 준수.

1. `BodyColliderAutoBuilder` — Humanoid 본 → 구/캡슐 콜라이더 자동 생성 (시메트리 활용, 크기 자동 산출 + 보정 계수)
2. `HairBoneChainDetector` — Head 미할당 자식 체인 + 본명 패턴(영/일) 감지 → 부위 분류(front/side/back/tail)
3. `CharacterPhysicsSetup` — 오케스트레이터: 콜라이더 생성 → 클로스 생성 → 프리셋+템플릿 적용 → ColliderList 매핑 → BuildAndRun
4. `PhysicsValidationProbe` — 검증: 애니메이션 재생 중 콜라이더 내부 진입 샘플링 + 결과 로그
5. (선택) 에디터 메뉴/인스펙터 — 원클릭 자동 세팅 + 감지 결과 프리뷰 + 수동 본 지정

규칙: MC2 파라미터는 직렬화 데이터로만 접근, 기존 FBXImporter/애니메이션 경로 미수정, 주석 한국어.

## 13. 구현 및 검증 결과 (2026-09-29 추가)

- `Assets/_Project/Tests/Editor/Physics/` — 단위·통합 테스트 29개 (`Tests.Editor.ClothPhysics`)

### 검증 결과
- EditMode: 물리 관련 29개 테스트 전부 통과 (전체 1663 중 실패 13개는 기존 FBXImporter/Settings 영역)
- YYB Miku 실측: Avatar 자동 복구 → 콜라이더 12개(대칭 포함 전신 커버) → BoneCloth 2개(Tail 6체인/Front 6체인)
- 플레이 모드: 두 클로스 모두 `valid/enable/running=True`, TeamId 할당, 꼬리 체인 본이 중력으로 ~1m 이동 확인
- 콜라이더 피팅: 머리카락 웨이트 포함으로 Head 반경 0.214m 과대 → 슬롯별 상한(maxR) 추가 후 0.100m로 정상화

### 중요 발견 — Enter Play Mode Options 비호환
- 프로젝트 설정 `m_EnterPlayModeOptions: 3` = 도메인 리로드 OFF + 씬 리로드 OFF
- MC2는 `RuntimeInitializeOnLoadMethod(SubsystemRegistration)`에만 초기화를 의존 →
  도메인 리로드 OFF에서 매니저가 생성되지 않아 클로스가 전부 무반응(IsEnable=False)이 됨
- 빌드에서는 문제없음(플레이어에서는 정상 초기화). 에디터에서만 발생.
- 대응 선택지:
  1. Edit > Project Settings > Editor > Enter Play Mode Options에서 Reload Domain 체크 (권장)
  2. 또는 세션당 1회 리플렉션으로 `MagicaManager.Initialize()` 수동 호출 (검증 시 이 방법 사용)

### 남은 리스크
- PhysicsValidationProbe의 침투 경고는 두피 근처 체인 본이 콜라이더 내부를 지나는 정상 케이스를 포함 →
  고정 루트 본 제외는 적용했으나 두피 근접 구간의 기준값 추가 조정 필요
- 다른 모델 범용성: Humanoid + 본명 패턴 fallback 검증은 YYB 1종에만 실측됨
- 시각 품질(흔들림 강도/감쇠)은 사용자가 씬에서 확인·조정 필요

## 14. 추가 안정화 결과 (2026-09-29 세션2)

### 구현
- `NamePatternBoneResolver.cs` 신규 — Humanoid가 아닌 모델용 본명 폴백 해석기
  (영어/일본어/MMD 로마자, 좌우 구분, 최장 키워드 우선 매칭)
- `BodyColliderBuilder` — 콜라이더 생성 후 `UpdateParameters()` 호출 (공식 필수),
  비균일 스케일 본 경고 추가, `MeasureTorso(hips,head)` 오버로드
- `CharacterPhysicsSetup` — Humanoid 실패 시 이름 패턴 폴백으로 자동 전환
  (콜라이더 미러 직접 생성 + 머리카락 탐지 동일 적용), ReapplyParameters 폴백 대응
- `PhysicsValidationProbe` — `minChainDepth` 옵션 + 초기 프레임 기저선 기록,
  **기저선 초과 침투만 경고** (두피 근접 본의 정상 내부 위치 오탐 제거)

### 검증
- EditMode: ClothPhysics 테스트 41개 전부 통과 (신규 6개 포함, 0.52s)
- 실측 플레이: ~5000프레임 + 120° 회전 2회 후 **초과 침투 0.0mm, 경고 프레임 0**
  → 이전의 47.9mm는 HD4 본의 정적 기저 내부 위치가 원인인 오탐이었음
- 컬링: MC2 기본값 AnimatorLinkage+AutomaticRenderer로 Animator 연동 자동 처리 확인 (추가 코드 불필요)

### 남은 리스크
- 기저선은 첫 샘플 프레임의 상태 — 시작 포즈가 이미 과도 침투면 기저선도 과대 (시작 후 수 프레임 정지 자세 권장)
- 외부 도구(ColliderBuilder/MC2Helper) 도입 불필요 — 자체 구현이 동등 이상
