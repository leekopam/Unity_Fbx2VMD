# 프로파일링 뷰어 GUI 개선 작업계획서

작성일: 2026-09-29
선행 문서: `Docs/report/perf-profiling-tool-guide.md` (도구 구조·한계), 조사 결과 요약(Profile Analyzer/Tracy/Perfetto/Unreal Insights/Graphy 대비)

## 용어

- 런(Run): `PipelineRunProfiler.BeginRun`~`EndRun` 1회 변환 세션. JSON 리포트 1개로 저장됨.
- 리포트: `Artifacts/Profiling/run-*.json` — 영속 데이터로 .pdata 포맷과 동일한 역할.
- findings: `ProfilingRunAnalyzer`가 생성하는 자동 진단 항목(Bottleneck/TrendRegression/FrameSpike/GcSpike/Failure).
- 임계값: `analysis-thresholds.json` + `ProfilingAnalysisThresholds` — 분석 판정 기준.

## 목표

사람이 런 이력을 **조작하고 관리**할 수 있는 뷰어 완성. 업계 표준 구조(Profile Analyzer의 "Single/Compare + 범위선택→집계 + 필터")에 맞춰 현재 창을 강화한다.

## 조사 근거 요약

| 출처 | 확인된 표준 기능 |
|---|---|
| Unity Profile Analyzer (공식, com.unity.performance.profile-analyzer) | Single/Compare 모드, 프레임 범위 선택→집계(min/max/mean/median/사분위), 필터, Top10 마커, 정렬 테이블, CSV 내보내기 |
| Unity Memory Profiler | 스냅샷 목록 + Compare + diff 컬럼 + 그룹화 |
| Tracy | 타임라인+플레임그래프, Find Zone 통계, Compare 트레이스, 카운터 플롯 |
| Unreal Insights | Frames 막대 패널, 스크럽 범위선택→Timings/Timers 집계, 로그 마커 |
| Perfetto | 슬라이스 트랙, 영역선택→집계, 핀/필터 — 타임라인 상세는 여기에 위임 |
| Graphy | 목표선(기준선), 임계 조건→액션 |

공통 최소 세트: 차트 범위선택→집계 통계 / 정렬 테이블 / 두 런 비교(diff) / 필터 / 기준선 / 영속 파일+내보내기 / 이상 표시.

## 현재 상태 요약

| 항목 | 상태 |
|---|---|
| 런 목록 + 상세 + findings + 추세 표 | 구현됨(`ProfilingReportWindow`, IMGUI) |
| Compare | 기본 수준(좌클릭 기준/우클릭 대상) — diff 컬럼 없음 |
| **프레임 시계열 데이터** | **미저장** — `_frameSamples`는 퍼센타일 계산 후 폐기됨 → 차트 선행조건 부족 |
| 임계값 편집 | JSON 직접 편집만 — 편집 UI 없음 |
| 운영 액션 | 메뉴 분산(Tools/Profiling/*) — 창 안에서 실행 불가 |
| 대용량 이력 | `BuildTrendRows`가 GUI 스레드에서 파일 스캔 |
| 상세 타임라인 | 없음 — Chrome Trace 내보내기는 있음(Perfetto 위임으로 커버, 재구현 금지) |

## 범위

**포함**
1. 프레임 시계열 저장 + 런 프레임 차트(범위 선택→집계)
2. 임계값 편집 패널(표시/수정/저장/기본값 복원/검증)
3. 운영 액션 통합(베이스라인 재측정, 배치 계측, HTML/Trace 내보내기·열기, 리포트 폴더 관리)
4. 스테이지 정렬 테이블 + 임계 초과 강조 + Top-N 비중
5. Compare 강화(기준/대상 고정, 스테이지별 Δms·Δ% diff, findings 비교)
6. 이력 로딩 개선(필터, 백그라운드/지연 로딩)

**제외**
- UI Toolkit 전면 재작성 — IMGUI 유지, 차트는 IMGUI 커스텀 드로잉(GUI.DrawTexture/메시). 줌·팬·호버가 복잡해지면 그때 차트만 UITK 부분 도입 재검토
- Perfetto급 슬라이스 타임라인 재구현 — `ProfilingTraceExporter` 출력을 `ui.perfetto.dev`/`about:tracing`에서 여는 진입만 제공
- 실시간(라이브) 스트리밍 뷰 — 리포트 파일 기반 사후 분석만
- JEV 진단 섹션 변경 — 유지

## 단계별 계획

### Phase 0 — 프레임 시계열 저장 (선행 데이터)

- `ProfilingRunRecord`에 `frameSamplesMs`(float[]) 추가 — schema v1 호환 유지(구 리포트는 빈 배열로 역직렬화)
- 크기 근거: 8707프레임 float ≈ 35KB/런 — 현재 수MB 리포트 대비 무시 가능. 다운샘플 불필요
- `EndRun`에서 `_frameSamples`를 그대로 기록하고 퍼센타일은 기존 로직 유지
- 테스트: 신규 필드 직렬화 왕복 + 구 리포트 역직렬화 호환

### Phase 1 — 런 프레임 차트 + 범위 선택 집계

- 상세 패널에 프레임 시간 막대 차트(IMGUI 커스텀 드로잉)
- 드래그 범위 선택 → 선택 구간 집계(프레임 수/min/max/mean/p95/GC 피크) 표시
- 기준선: `frameSpikeMinMs`(기본 33ms) 수평선 + 스파이크 프레임 색상 강조
- `frameSamplesMs`가 없는 구 리포트는 요약 통계만 표시(호환 분기)
- `BuildTrendRows` 이력 스캔을 백그라운드 로딩으로 이동(선택 변경 시 히치 제거)

### Phase 2 — 운영·관리 패널

- 임계값 편집 패널: 현재값 표시 → 수정 → 저장 → 기본값 복원 → 입력 범위 검증(음수/0 방지). 저장 후 목록 재분석 반영
- 액션 툴바: `베이스라인 재측정`(BatchOps.RebuildBaselines 호출), `배치 픽스처 계측`(RunFixtureProfile), `HTML 리포트`, `Chrome Trace`, `출력 폴더 열기`, `Perfetto에서 열기`(trace 파일 경로 표시+폴더 열기)
- 리포트 관리: 라벨/결과(성공·실패·중단) 필터, 날짜 범위 필터, 구형 대용량 리포트 식별 표시

### Phase 3 — 스테이지 테이블 강화

- 컬럼 정렬 가능 테이블: 스테이지/deltaMs/전체 비중%/호출수/누적ms
- 임계 초과(bottleneckShareOfTotal) 행 강조, Top-N 비중 요약
- 추세 행을 테이블과 통합(같은 스테이지의 과거 중앙값/배율을 별도 컬럼으로)

### Phase 4 — Compare 강화

- 기준(A)/대상(B) 선택 고정 표시 + 교체 버튼
- 스테이지별 Δms·Δ% diff 컬럼, findings 목록 비교, 입력 컨텍스트(크기/클립/본 수) 차이 표시

## 공통 규칙

- Plan→Patch→Verify→Report, 각 항목 완료 시 EditMode 테스트 1개 이상 동반
- schema v1 호환 유지 — 신규 필드는 구 리포트에서 기본값으로 역직렬화되어야 함
- 창 전체는 IMGUI 유지. 대형 리포트 로딩·스캔은 GUI 스레드 블로킹 금지
- 분석 로직(ProfilingRunAnalyzer 등)은 재사용 — 뷰어 코드에 판정 로직 복제 금지

## 가정

- 리포트 파일 크기 증가(+35KB/런 수준)는 허용 범위
- 임계값 파일은 에디터 세션 동안 수동 편집이 드묾 — 동시 편집 충돌 처리는 파일 다시 읽기로 충분
- 창 사용자는 이 프로젝트의 변환 파이프라인 개발자 1~2명 — 권한·잠금 UI 불필요

## 리스크

- IMGUI 차트의 인터랙션(호버·줌) 한계 → 범위 선택까지만 구현, 줌은 Phase 4 이후 필요 시 UITK 부분 도입
- 대형 리포트(구형 수천 스테이지) 로딩 시 창 지연 → 백그라운드/지연 로딩으로 완화, 완전 해소는 별도 최적화
- 임계값 편집 UI가 JSON 파일과 어긋나는 상태 → 저장 즉시 다시 읽어 표시값 갱신으로 방지

## 작업 지시 (worker brief)

Phase 0→1→2→3→4 순 구현. 각 Phase는 독립 커밋 단위로 완결(테스트 통과 + 실 리포트 표시 확인) 후 다음 진행.

## 수용 기준

- tetoris 실패 런 리포트에서 프레임 차트가 표시되고, 범위 선택으로 집계 통계가 나옴
- 임계값을 창에서 수정·저장하면 `analysis-thresholds.json`이 갱신되고 추세 판정에 즉시 반영됨
- 스테이지 테이블이 컬럼 정렬되고 Retargeting(비중 99%) 행이 강조됨
- 두 런 Compare에서 스테이지별 Δms/Δ%가 표시됨
- EditMode: frameSamplesMs 왕복, 구 리포트 호환, 임계값 저장-로드 왕복, 범위 집계 계산 테스트 통과

## 검증 계획

1. EditMode 테스트 전체(`Fbx2Vmd.Profiling.Editor.Tests`) 통과
2. `Artifacts/Profiling`의 실 런 리포트로 창 표시 확인(차트·강조·Compare)
3. 구형 대용량 리포트 선택 시 창 프리즈 없음(체감 또는 카운트)
4. 임계값 저장 후 `ProfilingRunAnalyzer.Analyze` 호출에 새 값 반영 확인
