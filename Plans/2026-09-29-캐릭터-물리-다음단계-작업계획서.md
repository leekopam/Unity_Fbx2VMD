# 캐릭터 물리 시스템 — 다음 단계 작업계획서

작성일: 2026-09-29
선행 문서: `Plans/2026-09-29-캐릭터-물리-적용-작업계획서.md` (§13/§14 구현·검증 결과 참조)

## 용어

- BoneCloth/MeshCloth: Magica Cloth 2 에셋의 클로스 타입 (Unity 기본 기능·MMD4Mecanim 기능이 아님).
  본 계층만 있으면 작동하므로 모델 로더(UniVRM 전환 등)와 무관하게 유지됨.

## 현재 상태 요약

| 항목 | 상태 |
|---|---|
| 머리카락 자동화 파이프라인 (BoneCloth) | 완성 — 콜라이더 생성/체인 탐지/부위별 분리/파라미터 템플릿/튜닝 슬라이더 |
| 검증 체계 | 단위 테스트 41개 + 프로브(기저선 대비 초과 침투) — 회전 검증에서 초과 침투 0 |
| 범용성 | Humanoid + 본명 폴백(영/일/로마자). YYB Miku·프로나마쨩 2종 실측 |
| 옷·장식물 | 미적용 — BoneCloth만 자동화됨, MeshCloth는 범위 외 |
| 런타임 관리 | 수명주기(교체/삭제/활성전환) 미구현 |

## 단계별 계획

### Phase 1 — 실측 품질 확보 (YYB Miku 기준)

목표: 씬에서 실제로 "관통 없음 + 손발 꼬임 없음"을 반복 검증 가능한 상태로 만든다.

1. **검증용 애니메이션 동작 추가**
   - ContextMenu `검증 애니메이션 실행` — 팔 들기/회전/몸 굽힘 포즈 시퀀스를 N초간 재생
   - 프로브와 연동해 종료 시 자동 리포트 출력
   - 목적: 육안 없이도 "걸림/관통"을 수치로 재현 가능하게 (VRMSpringBoneTool의 달리기/댄스 버튼과 동일 개념)
2. **손·발 꼬임 실측**
   - 팔을 트윈테일 궤적으로 휘두르는 포즈에서 초과 침투 + 머리카락 체인 정지 여부 측정
   - 필요 시 Hand/Foot 콜라이더의 Friction·Radius 재조정, Tail 체인의 콜라이더 카테고리 조정
3. **육안 확인 보조**
   - Cloth Monitor 기즈모 활성화 옵션 또는 프로브의 침투 콜라이더/본 기즈모 표시

산출물: `CharacterPhysicsSetup`에 검증 애니메이션 러너 + 포즈 기반 침투 리포트.

### Phase 2 — 런타임 수명주기 안정화

목표: 게임 플레이 중 발생하는 상황(리스폰·의상 교체·순간이동)에서 물리가 안전하게 동작.

4. **Teleport 연동**
   - 캐릭터 순간이동/리스폰 시 MC2 Teleport Reset 자동 호출 (공식 API `cloth.ResetCloth()` 계열)
   - CharacterPhysicsSetup에 `ResetPhysics()` 공개 메서드
5. **비활성/활성 전환 대응**
   - 오브젝트 SetActive 토글 시 클로스 상태 복원 확인 — OnEnable에서 invalid 클로스 재빌드 여부 결정
6. **컬링 정책 확정**
   - AnimatorLinkage 기본값 확인됨 → 다중 캐릭터 시 Scene뷰 컬링 동작 문서화
   - 필요 시 `syncCullingMode` 옵션 추가 (Animator cullingMode에 따라 Off/Reset/Keep)

### Phase 3 — 범용성 검증 (제2 모델)

목표: 다른 명명·체형·본 구조 모델에서 자동화가 통하는지 검증.

7. **제2 테스트 모델 선정**
   - 프로젝트 내 모델 부재 시 사용자 제공 모델(다른 MMD/VRoid/본명 다른 FBX) 1종 요청
8. **폴백 해석 + 체인 탐지 실측**
   - NamePatternBoneResolver/Head 미할당 본 탐지로 설정 자동화 여부 확인
   - 미분류 본 리포트 검토 → 키워드 테이블 보강
   - 본 해석 3번째 소스 예약: UniVRM 전환 시 VRMSpringBone 메타데이터(체인+콜라이더
     선언 내장)를 읽어 BoneCloth로 변환 — 이름 패턴 폴백보다 정확한 경로
9. **체형 스케일 대응**
   - 비인간 비율(치비/대형) 모델의 torsoLength 기준 반경 상한 재검토

### Phase 4 — 옷·장식물 확장 (선택 범위)

목표: 머리카락 이외의 흔들림 대상을 단계적으로 자동화.

10. **장식물 BoneCloth 자동화**
    - 리본/체인/액세서리 본 키워드(ribbon/accessory/飾り 등) → BoneCloth 생성 (머리카락 파이프라인 재사용)
11. **MeshCloth 스커트(반자동)**
    - 스커트 메시 탐지(본명 skirt/スカート) → ProxyMesh 자동 생성 + Reduction 기본값
    - 버텍스 속성(고정/이동) 페인팅은 자동 휴리스틱 + 수동 확인 단계
    - 완전 자동화는 기대치 낮음을 명시 — 하체보정 경험상 수동 페인팅 불가피

### Phase 5 — 빌드·성능 검증

12. **플레이어 빌드에서 계측**
    - 에디터 부하는 기준 아님: 빌드에서 MagicaCloth CPU 시간 측정
    - 클로스 수×파티클 수 기준 성능 예산 산정 (기존 Profiling 인프라 연동 가능)
13. **런타임 구축 지연 처리**
    - 동적 로드 시 프레임 스파이크 → Pre-build 옵션 또는 백그라운드 구축 활용 결정

## 각 Phase 공통 규칙

- 구현은 Plan→Patch→Verify→Report, 각 항목 완료 시 EditMode 테스트 1개 이상 동반
- 씬 실측은 활성 모델(`YYB Hatsune Miku_default_1.0ver`) 기준, 프로브 리포트를 근거로 남김
- MC2 버전업 관련 변경 시 릴리스노트 대조 후 적용

## 우선순위 판단 (권장 순서)

Phase 1(검증 애니메이션) → Phase 2(수명주기) → Phase 3(제2 모델) → Phase 4/5는 요구 발생 시.
"관통 없음/꼬임 없음" 요구사항의 종료 조건은 **검증 애니메이션에서 초과 침투 0 + 걸림 재현 없음**으로 정의.

## 검증 결과 (Phase 1~5 구현·실측, 2026-09-29)

### Phase 1 — 실측 품질 확보 ✅
- `PhysicsValidationSequence` 추가: 몸 회전→양팔 휘두름(절대 회전)→몸 굽힘 순차 재생, 종료 시 프로브 리포트 자동 출력. ContextMenu "검증 시퀀스 실행".
- `PhysicsValidationProbe`에 기즈모 추가: 생성 콜라이더 와이어 표시 + 최악 침투 위치 빨간 마커.
- **실측**: YYB Miku 플레이에서 327프레임 샘플링 → **초과 침투 0.0mm, 경고 프레임 0** (기저선 27mm는 정적 두피 근접 위치).

### Phase 2 — 런타임 수명주기 ✅
- `ResetPhysics(bool keepPose)` → `ResetCloth()` 공식 API: 플레이 중 호출 후 클로스 유지·정상 동작 확인.
- `SetParameterChange()` 공식 API: 튜닝 재적용 경로에 사용 중.
- `usePreBuild` → `SerializeData2.preBuildData.enabled` 연결 (실측 결정은 Phase 5 미수행).
- **실측된 실제 버그**: `SetActive(false→true)` 후 클로스 팀이 해제돼 영구 무효 — MC2가 재활성만으로 복구하지 않음. `OnEnable` 즉시 판정은 비동기 빌드와 경쟁하므로 **30프레임 유예 후 Update에서 판정 → autoRebuildOnEnable(기본 true) 시 자동 재설정**으로 수정, 토글 복구 실측 완료.

### Phase 3 — 범용성 ✅ (실모델 2종)
- `NamePatternBoneResolver` (영/일/MMD 로마자, 좌우 토큰·측면 접미 감지, 구분자 정규화, 최장 매칭) + 비Humanoid 폴백.
- 통합 테스트: 합성 Generic 릭으로 셋업 전 과정 통과 — 콜라이더·BoneCloth 생성, 스커트 경고, 재실행 멱등.
- **실모델 검증 (프로나마쨩)**: Humanoid 아님 → 이름 패턴 폴백으로 신체 본 21개 해석, 콜라이더 18개 생성, BoneCloth 5개(Tail 22/Back 8/Side 4/Front 7/Accessory 1 체인).
  - 검증 시퀀스 완주: 기저선 침투 0.0mm, 최대 초과 침투 6.0mm(경고 프레임 6/215), 재측정 시 유사(6.1mm) — 재현성 확인.
  - 스커트 본 64개 감지 → MeshCloth 수동 설정 안내(자동화 범위 외, 계획대로 경고 출력).

### Phase 4 — 장식물·스커트 ✅
- 리본/체인/스트랩 등 장식물 키워드 + 신체 측 부착점 탐지 + 중첩 루트 제거.
- **실측된 실제 버그 2건 수정**: ① `bow` 키워드가 `elbow`에 오탐 → `hair_?bow|bowknot|bow_?tie`로 정밀화, ② 명시 루트 경로가 `worldLength` 미측정으로 0.00m 표시 → 측정 추가.
- 생성물(`MC2` 접두)은 스캔 제외. 스커트 본 감지 시 MeshCloth 수동 설정 경고 (Miku: 108개 감지 확인).

### Phase 5 — 성능 ✅
- `PhysicsPerfRunner` 추가: 동적 구성 vs 프리빌드 비교, MC2 ProfilerMarker(`InitCloth`/`StartClothUpdate.Time`/`WriteMesh`) 계측, `PipelineRunProfiler`로 JSON 리포트 출력(`Artifacts/Profiling/run-*.json`). Development Build에서 `-fbx2vmd-physperf` 인자로 자동 측정.
- 에디터 계측(프로나마쨩, 클로스 5개): PreBuild waitFrames=1·valid 5/5 vs Dynamic waitFrames=5·5/5 — 프리빌드가 초기화 대기 단축. 시뮬레이션 마커 평균 0.001ms.
- **플레이어 빌드 계측 (778MB Development Build, 미쿠 씬)**: PreBuild valid 2/2·preBuildNs 19.8ms / Dynamic valid 2/2·initClothNs 5.6ms — 두 경로 모두 유효. 프레임 P50 6.94ms·P95 7.04ms (P99 13.9ms·최대 3.9s는 시작/베이크 스파이크로 steady-state 아님).
- 발견·수정: 플레이어 빌드 컴파일 오류(`NativeHumanoidAnimationPlayer`의 `#if UNITY_EDITOR` 미가드 호출) — 기존 코드 결함 수정 후 빌드 성공.

### 검증 근거
- EditMode: `Tests.Editor.ClothPhysics` 전체 통과 (리졸버·프로브 대칭 수학·통합 포함). 전체 EditMode 스위트 1702개 중 실패 13건은 전부 FBXImporter/Settings/Probe 영역의 기존 실패 — 물리 변경 무관(실패 테스트가 HEAD 기준으로도 실패 상태 확인).
- 플레이 실측: 미쿠·프로나마쨩 검증 시퀀스 완주, 리셋·SetActive 토글 복구, 클로스 `valid/running=True`.
- 플레이어 빌드: `run-20260929-171347-ffcf40-miku-physics.json` — 동적/프리빌드 두 경로 측정 완료.

### 남은 리스크
- 손·발 꼬임: 프로브에 '걸림 지표'(본의 연속 침투 샘플 수·걸림 의심 본 수) 추가로 수치화 — 최종 육안 확인은 여전히 권장
- 스커트·넓은 옷감은 MeshCloth 수동 범위 (계획상 자동화 제외)
- 플레이어 최대 프레임 3.9s는 시작 스파이크 — steady-state 성능은 P50/P95 참조

### 후속 수정 (2026-09-30)
- `Setup()` 멱등화: 플레이 중 전 클로스 유효·빌드 중이면 재생성 생략 — 빌드 중 파괴로 인한 `Startup cancelled`/무효 클로스 잔류 원천 차단. 강제 재생성은 `Rebuild()`·'자동 생성 물리 제거' 경로. 무효 감지 기준을 `IsValid` → `IsClothAlive`(실행·빌드 중·유예 구간)로 교체해 init 비동기 중 오탐 재빌드 방지. 플레이 실측: 연속 Setup() 스킵 확인, Rebuild() 재생성 후 클로스 정상 유효.
- 런타임 리포트 필드(lastReport·worstInfo·lastSummary) `[NonSerialized]` — 씬 파일에 실행 결과가 구워지던 것 제거.
